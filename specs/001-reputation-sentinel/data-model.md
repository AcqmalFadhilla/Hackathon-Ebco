# Phase 1 Data Model: Reputation Sentinel Ops

Derived from spec.md "Key Entities". Field names are illustrative for planning/tasks
purposes, not a final schema contract.

## Branch

Represents a physical business location connected to a Google Business Profile.

| Field | Type | Notes |
|---|---|---|
| `branch_id` | string (PK) | Internal identifier |
| `name` | string | Display name |
| `address` | string | For display/context only |
| `gbp_location_id` | string | Google Business Profile location reference |
| `manager_id` | string (FK → Manager) | Assigned per Assumptions (one manager per branch) |
| `oauth_credential_ref` | string | Pointer into Secret Manager, never the raw token (Security & Data Handling) |
| `connection_status` | enum: `connected` \| `disconnected` \| `error` | Surfaced in UI |
| `last_ingested_at` | timestamp | Drives the 15-minute freshness target (SC-001) |

## Review

A customer-submitted rating + text tied to a Branch.

| Field | Type | Notes |
|---|---|---|
| `review_id` | string (PK) | Google's review identifier |
| `branch_id` | string (FK → Branch) | |
| `rating` | integer 1-5 | From FR-002 |
| `text` | string | Sensitive — logging-restricted per Security & Data Handling |
| `reviewer_name` | string | Sensitive — logging-restricted |
| `posted_at` | timestamp | |
| `language` | enum: `id` \| `en` \| `other` | FR-005; `other` still ingested, accuracy not guaranteed (Assumptions) |
| `sentiment` | enum: `positive` \| `neutral` \| `negative` | FR-003 |
| `topics` | array<string> | FR-004, e.g. `["service", "cleanliness"]` |
| `severity` | enum: `routine` \| `urgent` | FR-006/FR-007 |
| `status` | enum: `new` \| `analyzed` \| `drafted` \| `approved` \| `published` \| `rejected` | See state machine below |
| `existing_owner_reply` | boolean | Edge case: review already had a manual reply before ingestion. When `true`, FR-020 requires the review to skip the draft-and-approve flow entirely and be shown as already-answered. |

**Review status state machine**:

```text
new → analyzed → drafted → approved → published
                     └────→ rejected → (back to drafted, new draft generated)
```

- `new`: ingested, not yet analyzed.
- `analyzed`: sentiment/topics/severity set (Analysis + Triage agents done).
- `drafted`: a Draft Reply exists, awaiting manager action.
- `approved`: manager approved (with or without edits) — triggers publish attempt.
- `published`: publish confirmed (FR-013 status check passed).
- `rejected`: manager rejected — system returns the review to `drafted` with a newly
  generated Draft Reply per Edge Cases handling (never stays permanently stuck).

## Draft Reply

An AI-generated candidate response to a Review.

| Field | Type | Notes |
|---|---|---|
| `draft_id` | string (PK) | |
| `review_id` | string (FK → Review) | One active draft per review at a time |
| `content` | string | Generated by Draft Agent, editable by manager before approval |
| `status` | enum: `pending` \| `approved` \| `rejected` \| `published` | Mirrors Review status transitions relevant to the reply itself |
| `approved_by` | string (FK → Manager), nullable | FR-014 accountability record |
| `approved_at` | timestamp, nullable | |
| `publication_state` | enum: `not_submitted` \| `pending` \| `approved` \| `rejected`, nullable | Tracks the external reply-moderation outcome checked per FR-013 |
| `edit_distance` | integer, nullable | Difference between generated `content` and the manager-approved final text; recorded at approval time to measure SC-006 |

## Branch Health Score

An aggregated, per-branch metric over a period, used for the digest (FR-015/FR-016).

| Field | Type | Notes |
|---|---|---|
| `branch_id` | string (FK → Branch) | |
| `computed_at` | timestamp | |
| `score` | number | Aggregates sentiment mix + response rate + urgent-review count over the period |
| `top_topics` | array<string> | Most frequent complaint topics for the period (FR-016) |
| `urgent_count` | integer | Count of `severity = urgent` reviews in the period |

## Manager

A user responsible for one or more branches.

| Field | Type | Notes |
|---|---|---|
| `manager_id` | string (PK) | |
| `name` | string | |
| `google_identity_email` | string | The authenticated identity (FR-019) this manager record maps to; `approved_by` on Draft Reply is populated from this, not free text |
| `branch_ids` | array<string> (FK → Branch) | Branches this manager is scoped to (Assumptions: one manager per branch, but a manager may cover several branches) |
| `alert_channel` | enum: `in_app` | Fixed to in-app/dashboard only for MVP (Assumptions — no Slack/email) |

## Relationships

```text
Manager 1───* Branch 1───* Review 1───1 Draft Reply
                  │
                  └───* Branch Health Score (computed, not stored per-review)
```
